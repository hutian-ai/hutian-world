# hutian-world

- Product: a Web workspace for persistent roles and human-coordinated projects. Creators, roles, projects, business grants, tasks and acceptance belong here. Native Harnesses own inference, local assets and sessions.
- Stack: React / Vite / React Router / Tailwind / shadcn-style Radix primitives, NestJS with Fastify, TypeORM with PostgreSQL, TypeScript and pnpm. Use the independent ../hutian-design project for shared UI and chat components; do not copy its components back into Web or copy old database/workflow infrastructure.
- Web is a pure frontend and produces static assets. Keep business authorization, module credentials, filesystem access, background coordination and tool implementations in `apps/api`. Do not add Server Actions, business API handlers or runtime secret reads to Web; its local server only serves assets and forwards same-origin API requests.
- Web updates must use the package `build` script, which stages and validates Vite output before atomically replacing the HTML entrypoint and retaining prior hashed assets. Never clear or build directly over the served `dist/` directory. Web-only asset updates do not require restarting the API or execution host. After changing this update path, check an already-open tab navigating after a build, in addition to a fresh page. Frontend rollback restores only the previous HTML entrypoint, not API code or data.
- `apps/api` is the Hutian application server. Browser commands, background work and Dock callbacks share its application services and current access context. No API-to-Web callbacks or authenticated self-HTTP calls. Preserve the independent execution host and its original Dock application identity.
- For relevant feature work, consult `../docs/development-references.md` for the collected product and module references, then inspect only the current upstream mechanisms needed. References do not expand MVP scope or override the product and system design.
- For UI changes follow `DESIGN.md` and `.agents/skills/hutian-world-ui/SKILL.md`. For shared UI or Chat rendering, open ../hutian-design/AGENTS.md and its DESIGN.md task index; edit the owning component there. Web owns product composition, native-event projection and authenticated callbacks. Use assistant-ui for conversation history, threads and composers.
- Full-page navigation uses `PageNavigation` and the shell's single breadcrumb. Do not add local breadcrumbs or duplicate back arrows to object headers. Preserve explicit cross-section return destinations, URL selection/filter state, narrow-screen directory returns and unsaved-form guards; see DESIGN.md's 2026-11-17 navigation rules.
- Prefer small complete usable stages. The first stage has members, local private chat, projects, project-role membership and Dock connection settings. Keep empty states and real error handling; do not seed invented online Agents, execution results or metrics.
- Latest completed stage stays uncommitted for review. Explicit approval to start the next stage authorizes a local commit of the previous stage alone. Do not push, publish, create public repositories, issues or PRs without specific authorization.
- Do not add tests, test frameworks, fixtures, CI or broad validation matrices unless the user requests them. Use the shortest real interaction path and necessary compilation checks.
- For JS/TS commodity utilities, consider suitable UnJS packages first, then other community packages. Official service SDKs and specialized drivers remain appropriate.
- Keep module-owned facts in their modules: Matrix owns messages, Hindsight owns memory, the knowledge service owns documents/indexes, Dock/native Harness owns execution. hutian stores business relationships and references.
- 2026-11-16 scheduled work: schedules belong to a member, without task-level Runtime/model or delivery-room selection. Snapshot member configuration when the occurrence is created; preserve queued/running and historical snapshots. Each new occurrence automatically gets its own Matrix work conversation. Inbox notices reference that run; reading never resolves an approval or changes execution state. Calendar/history open the same work. Chat text is the default result, with no default ZIP or output-directory delivery requirement. See docs/member-schedules-inbox-2026-11-16.md; this remains stage 7, uncommitted.
- Runtime-private memory, knowledge, Skills and credentials are not scanned or synchronized. Rebinding a role does not replay or migrate an in-flight task.
- Use a separate PostgreSQL database and non-admin application role. Local workspace infrastructure is under ../infra/postgres; independent installs can supply their own PostgreSQL. Credentials, receipts, evidence and runtime logs stay under ignored .local/ with private permissions. Never print passwords or connection strings.
- The first stage is a trusted local single-creator workspace. The backend establishes an HttpOnly/SameSite browser session and validates origins. Application/module credentials stay server-side; never put them in browser build variables or treat this as multi-user authentication.
- No production data reset, destructive migrations or automatic old-data migration. Use explicit versioned migrations, synchronize:false, and preserve stable role IDs independently of project membership.

- 2026-11-17 架构规范：当前技术边界统一见 `docs/architecture.md`。应用用例位于 API `application/`，传输适配位于 `transport/browser/`；后台直接调用用例，不恢复伪 HTTP 或全局服务定位器。新 JSON 接口使用 v2 envelope/错误码和共享 schema；v1 仅兼容旧页面。持久副作用独立记录，保持原请求/运行 ID；数据库特定原子写放在有作用域 Repository。依赖方向由现有 ESLint 检查。交付及验收见 `docs/architecture-delivery-2026-11-17.md`。
