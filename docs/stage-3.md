## 本段实现

- 成员详情与目录提供真实“发消息”入口。首次明确打开私聊或邀请成员时，通信模块用既有 Application Service 无密码机制创建受管身份；角色与通信身份的正式关系保存在 hutian 的 `role_chat_identities`，不由浏览器偏好代替。
- 同一角色在私聊、群聊与频道复用相同通信身份。重复打开私聊沿稳定 Matrix 别名回到原房间；加入房间本身不会启动模型。
- 每次新执行由 hutian 服务端读取当前拥有者的角色定义，构造身份、职责和人设指令。执行宿主只接收通用的调用方指令和来源元数据，不拥有 hutian 的角色业务。
- 原请求保存这次角色定义的时间与内容 hash、名称、来源、所选 Runtime 及实际提示。修改人设影响后续新请求，重新观察旧运行仍使用原提示、连接和回执。
- 消息运行详情展示本次成员、人设版本、所选 Runtime 与原运行编号。到成员配置的链接明确表示当前配置，不能冒充原历史版本的编辑页面。
- 本次还修正了刷新后 Runtime 已选值没有显示名称的问题；重新发现时若原入口已不可用，会要求重新选择，派发仍需服务端核对。
- 补齐成员“设置 → 执行配置”：真实读取在线电脑与 Harness，可保存、切换或清除成员默认 Runtime。概览展示当前默认并提供直达入口；聊天区区分“成员默认”和“临时”选择。服务端在新请求派发时解析当前绑定，不可用时明确报错，不自动换电脑。
- 浏览器临时选择关联成员执行配置的修订时间，修改默认后旧缓存不能继续覆盖新值。变更默认不修改人设定义版本，也不影响原运行的目标与回执；执行端的模型、思考强度及权限继续沿用原生配置。

## 数据与模块边界

新增显式 migration 创建 `role_chat_identities`：以 role_id 为主键和 roles 外键，agent_id、user_id 各自唯一。创建关联按拥有者范围核对并锁定角色；已有身份不同则拒绝静默替换。应用仍使用本机独立 PostgreSQL 数据库和非管理员账号。

另由显式 migration 创建 `role_runtime_bindings`，持久保存可选的成员默认电脑、Harness、公开名称快照和独立修订时间。写入按拥有者范围锁定角色并检查调用方读到的修订时间；与人设和通信身份各自独立。只读数据库面板账号已获得新表查询权限。

Matrix 新增可选宿主的受管助手创建 / 更新接口，身份会话和 Agent device ID 保留在模块私有配置中。已有老账号的部署由运维增量登记 AS；本机在保留原账号、房间与数据库的基础上增加注册，私有配置变更前有备份。独立干净安装已有同样的 AS 准备机制。通用指令、版本、来源及 Runtime 元数据随原操作冻结，不扩展原生工具权限。

知识与记忆仍为当前创造者工作台范围，本段不声称完成角色私有资源授权。原生 session 持续恢复、模型工具与审批 UI、执行中追加 / 取消、任务编排也不属于本段。宿主仍串行处理，新角色不意味着支持并发模型执行。

## 怎么使用

打开 `http://127.0.0.1:3340/members`，进入墨菲的“设置 → 执行配置”保存默认 Runtime，再点击“发消息”。也可不设默认，在聊天中临时选择本轮 Runtime。群聊和频道的“成员”里可邀请角色，新建会话时也可直接选择成员。回复旁展开运行详情可核对这次的角色、人设版本与 Runtime。
