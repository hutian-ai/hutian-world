# 设备名称归属与改名交付（2026-11-17）

设备默认显示 Dock 的 nodeId。用户在「运行环境 → 设备详情 → 修改名称」手动填写后，Hutian 使用该名称；留空保存或点击「恢复编号」回到 nodeId。设备列表、详情、成员执行配置和聊天执行记录统一读取手动名称。同一设备上的各 Harness 共用名称，名称不参与身份识别或执行路由。

## 业务与数据边界

- 手动名称属于 Hutian 空间，由现有 API 和 PostgreSQL 保存。新增 `runtime-devices` 模块和 `runtime_device_settings` 表，不新增服务或数据库。
- 记录以 `workspace_id + connection_id + source_key + node_id` 唯一定位。现有 Dock 连接是可重新导入凭据的单一槽位，`source_key` 由规范化 endpoint 与 clientId 生成摘要，用于隔离不同接入来源；不包含 token，轮换 token 不丢失名称。更换 endpoint 或 clientId 后默认显示编号。
- `custom_name` 默认为空；只接受用户显式修改，不回填 Dock 旧 label 或机器 hostname。名字去除首尾空白，最长 80 字符，拒绝控制字符。保存 `version`、`updated_by` 和 `updated_at`；这是最后一次修改信息，不另建完整改名日志。
- 服务端校验当前空间管理者、所属连接和宿主返回的设备授权。仍在授权目录里的离线设备可以改名；无法确认授权时保留原设置并返回错误。
- 在事务内锁定连接行，并校验客户端版本；旧页面不能覆盖更新后的名称。切换接入来源也拒绝旧页面保存。名称按空间和来源保留，不因设备暂时离线清理。
- Dock 的设备身份、配对、原生设置与执行账本继续由 Dock 管理；Hutian 不改写 Dock Server 的旧 label。历史原任务快照保留提交时内容，聊天页面按 nodeId 显示当前手动名称或编号。
- Web 只经现有会话和命令白名单读写 API，设备授权查询复用原执行宿主的 `/api/runtime`，不创建竞争的 Dock SDK 连接。
