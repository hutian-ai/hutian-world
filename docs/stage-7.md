## 从用户视角使用

打开 **http://127.0.0.1:3340/chat**，私聊直接描述工作；群聊／频道用 `@` 选择已加入成员，不点名时保存普通消息。Runtime、模型和推理等级统一归成员：私聊顶部快捷修改该成员模型／推理，运行环境进入成员执行配置；群聊通过“成员 → 执行配置”分别查看和修改。输入区不再放执行配置，没有讨论／执行模式切换，私聊、群聊、频道与现有角色身份不重建。

- 运行中显示原生公开进度与工具。确认执行结束后过程默认收起；手动展开优先，工具详情的开合独立保留。答案和真实文件在过程之外。没有过程的工作不显示空过程块。
- 原生支持时可补充当前工作，或明确排下一轮；补充保存为真实 Matrix 消息，再送入原运行。已接收、未接收与未知分别展示。停止发给原生运行，页面退出和刷新不停止任务。
- 下一轮可移除。当前工作停止／失败／未知时，同会话工作序列暂停，明确点击“开始处理”后继续。移除项保留消息及取消记录，协调器不会再次派发。其他独立会话仍可使用释放的入口。
- 审批、原生问题和授权链接留在工作附近。支持 options、原生标量表单及 URL 请求；不能呈现的复杂表单明确提示在执行端处理。决定提交、送达与工具结果分开。终态后的请求只读。
- 可附加五份文件，每份最多 8 MiB、总计最多 16 MiB。上传至 Matrix 原生媒体，原消息保存来源、大小和哈希。文件只有完成上传才可随消息提交；不自动加入知识索引或私库。
- 成果文件从原运行输出目录真实收回；下载再校验哈希。文本、Markdown、JSON、CSV、YAML、日志及 diff 可预览；其他格式下载后打开。输出回流不明时可补取原成果，不重跑模型。代码差异仅在原生确实提供 diff 时展示。
- 答案可复制、引用、保存为记忆／知识资料，或“请另一位继续”。保存前可编辑并选择个人或当前会话范围，附原消息和来源版本；交接形成引用原回复的新消息与新运行，不修改作者，不自动分享角色私库。
- 更早消息按 Matrix 游标加载；现有文字暂存和过程开合保留在当前浏览器对应会话，草稿功能不扩展。新工作使用成员默认配置，旧会话覆盖已停用；已接受、已排队和历史执行仍保留原快照，消息、排队与执行记录分别沿原权威保存。

## 技术与权威边界

Matrix 保存通信正文、回复关系和媒体。可选宿主持有原 job、原 Dock 回执、事件快照、控制意图和收回文件；独立执行进程不依附网页连接。Dock 和原生 Harness 决定实际执行状态。hutian API 保存 `chat_requests` 的空间、请求人、连接与冻结要求；Web 按当前身份、会话成员与原消息校验操作。

浏览器通过 SSE 接收独立运行活动更新，并以每秒会话快照核对历史与状态；活动变化由宿主监听原运行活动文件，不再等待全会话刷新。不是逐 token 差分协议，也不是第二套消息账本。单轮过程最多保留 300 个原事件，截断明确提示，正式回复和已收回文件继续保存。私有模型推理不进入公开过程。

DBOS 固定 `5.5.0`，在现有 PostgreSQL 的 `dbos_chat` schema 持久协调聊天与定时运行。聊天先落业务意图，再以 `chat:<workspace>:<request>` 启动；启动确认间隙由扫描补同一 workflow。定时 tick 仍计算到期实例，派发与观察改为 `schedule:<workspace>:<occurrence>` 的 DBOS workflow，不再由旧 timer 直接执行派发。

DBOS 只协调“派发／等待／核对／交付”，不包住原生推理循环。所有重试沿原消息、job 和回执；有原记录而结果未知时不创建替代 run。停止业务观察不能替代原生停止。Matrix 的持久队列是可选宿主的串行入口队列；Hutian 仍持有用户业务请求，不把通信模块变成角色或项目后端。

普通聊天与新定时任务统一使用 Dock SDK 桥接，消费原运行的活动、控制和成果。2026-11-16 按用户纠正，移除 Hutian 富途工具白名单及任务专用自动审批分支，原生 Harness 决定工具访问与权限；Hutian 仅呈现原生待授权请求、拒绝或失败，以及最终交付。旧运行保持原回执和冻结配置，不迁移在途推理或更换身份。

新增显式 migration `ChatRequests1794771000000`。迁移前已备份业务库；没有使用 TypeORM synchronize。原五个股票安排、周期、规则与持仓文件、原始结果附件保留。
