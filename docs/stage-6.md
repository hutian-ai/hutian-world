# 第 6 段：单人工作台的身份与空间边界

2026-11-15。用户要求提前预埋多人 / 多租户的最小基础，继续交付单人工作台。这里的“空间”是后端数据归属范围，不新增组织、企业或工作台切换界面，也不把产品叙事的“世界”直接定义为租户。

第 5 段已单独本地提交为 `61e65e6`，配合的 Matrix 第 19 段为 `10b6443`，未推送。当前第 6 段保留未提交。本段不增加登录、邀请、跨人共享、计费或第二套执行账本。

## 现在具备什么

- 用户、空间、空间成员关系与角色创造者归属分开保存。现有创造者经本机身份适配器映射到默认用户和默认空间，原角色 / 项目 / 会话 / 任务标识保留。
- API 在入口解析服务端身份，经 AsyncLocalStorage 贯穿业务调用。角色、项目、安排和运行的读取 / 写入同时检查空间和拥有者范围；业务服务不再自行读取固定创造者配置。当前适配器仍只接受本机应用凭据，不接收浏览器指定的用户、创造者或空间。
- 角色 / 项目归属、角色通信 / Runtime 关联、项目成员关联、任务与运行有显式空间字段；复合外键防止把不同空间的对象关联起来。创建人和角色创造者继续分别保存。当前数据仍按个人所有权读取，没有把“同空间”解释为自动共享私人内容。
- 模块连接记录明确所属空间和用户，仅保存连接引用，不保存或盘点上游私人资产。Web 使用私有 `access-bindings.json` 校验当前身份与原本机 Matrix、Dock、资源和附件连接的对应关系；没有匹配绑定就拒绝，不借用默认连接。
- 每期运行保存空间、请求人、执行身份、通信连接和 Runtime 连接。后台进入明确上下文，派发前重新核对成员与连接；Web 内部入口也核对请求与原运行一致。原消息、原 job / receipt 和冻结工作要求仍沿原链路继续，不重新派发未知执行。

## 数据与本机连接迁移

显式 migration `WorkspaceAccess1794770000000` 创建 `app_users`、`workspaces`、`workspace_members`、`module_connections`，并给已有业务表回填默认范围与归属。不重建现有角色或模块数据，不启用 TypeORM synchronize。

已有私聊别名和角色私有 / 会话共享资源的命名使用默认空间保存的旧资源命名空间，保持原知识空间、记忆 bank、凭据文件和原件目录可继续读取；迁移不重新计算成新的上游资源。未来空间需要自己的命名空间和连接，不能直接复用现有默认资料。

升级步骤：

1. 按已有方式备份本机业务库，运行 `pnpm db:migrate`。
2. 启动 API，使本机身份适配器准备默认上下文。
3. 运行 `pnpm access:setup`，核对原本机连接并写入私有归属文件；已有不同绑定不自动覆盖。
4. 启动 / 重启 Web。原连接文件仍留在原位置，不复制或修改原生配置。

首次安装也按同样顺序，在 API 启动后运行一次 `access:setup`。这仍是可信本机单人版本；没有公开的空间选择或用户冒充入口。

## 已核对与实际限制

- 必要编译与正式构建通过；没有新增测试代码、fixture、框架或依赖。
- 迁移后、实际派发核对前，原业务表的旧字段、记录数与标识逐条比较一致；原 5 个股票任务继续启用，美股每日 06:00、其他四项原周期保留。原模块凭据文件摘要和资源目录命名一致。
- API 能返回当前默认用户、空间和模块连接引用。带伪造空间头的请求被拒绝；错误空间的项目 / 角色关联被数据库复合外键拒绝并回滚，没有写入异空间记录。
- 真实浏览器读取沟通、知识、记忆、Runtime、定时列表与原日报附件通过，未发现页面脚本错误或横向溢出。
- 一次性安排到点自动生成带身份范围的原消息和 Dock 回执，最终从原回复确认“身份与空间迁移核对通过”；原运行标识保留。完成后仅删除核对安排，实际运行历史仍保留。该核对产生一条新的安排和运行，旧记录没有替换。
- 内部派发入口收到不匹配的空间时明确阻止；原附件在错误连接绑定下返回 404，恢复原绑定后返回 200，未回退到默认附件连接。模块绑定设置命令重复运行保留原配置。

本段仅打通本机身份适配器。另一位真实用户的登录、会话凭据、成员邀请 / 撤销产品流、共享授权以及独立 Matrix / Dock 接入尚未实现，也没有声称完成双租户端到端隔离验证。连接归属校验与数据外键是后续接入的基础，不能代替完整身份系统。

当前后台只处理默认本机用户的安排，不宣称多空间调度或跨用户代执行已完成。身份或连接不匹配时保留原运行等待核对，不把权限变更解释为可以换人重试；已经进入原生执行的工作不因本段自动取消。

私有迁移前备份、实际运行与浏览器证据在根 `.local/stage-6-access/`。后续多人设计可以替换身份入口并扩展连接解析，但必须继续按模块正式身份与当前授权执行。
