# Hutian 产品界面详细规则

从原 DESIGN.md 分离。只在修改对应工作面时定向读取；涉及旧 Core、World 或尚未开放能力的历史条款不代表当前已实现，也不扩展当前 MVP。当前产品 DESIGN.md 的 2026-11-15/16 裁决优先。通用组件与主题统一见 ../../../hutian-design/DESIGN.md。

### 5.3 一级工作面与详情页

World 工具栏已经承担全局位置，因此每个一级入口从工具栏下方直接展开为一块连续工作面，不再先放宽幅
`PageHeader`，再用同名 `Panel` 重复一次标题。目录、表格或 Action Center 等一级页使用紧凑工作面头：左侧只保留
页面标题、一个回答“这里做什么”的短句和必要计数，右侧最多一个主操作；筛选、Tabs 与结果列表紧接其后，属于同一
工作面。

2026-11-17：完整详情页通过 `PageNavigation` 将真实对象路径注册到顶部唯一的 Breadcrumb；正文单一对象头收拢身份、状态、关键上下文与一个主操作，不再放局部路径或同目的返回箭头。跨栏目来源返回和窄屏分栏返回必须明确去向，与所属层级分开。详见 DESIGN.md 的导航规则及设计包 docs/components.md §6.9。
对象级一级 Tabs 紧邻对象头；页面正文通过
分隔线、背景明度和留白形成连续章节，仅在表格、表单或确实独立的控制组需要边界时使用完整 Panel。

常规一级页和详情页继续使用文档流滚动，不为视觉统一强制占满视口。只有需要持久在线目录、独立滚动内容或底部操作的
任务工作面（例如沟通）才使用剩余视口全高。详情页可使用一个窄侧栏承载次要摘要，但主内容必须保持单一阅读顺序，
不得形成同权重卡片瀑布。

窄屏下工作面头和对象头重新排列为单列：返回路径位于身份之前，主操作保持至少 42px 触控高度，状态和元数据允许换行；
Tabs 与宽表格只在自身容器内横向滚动，不能造成页面级横向溢出。

三个主要工作面不得相互复制：沟通负责发起和持续协作，工作负责明确负责人、执行、交付与验收，概览只保留少量摘要、
最近动态和进入专用工作面的入口。Project 是多项 Task、Conversation 或 Document 的可选长期归组，不作为开始沟通、创建
Task 或获得权限的前置条件；工作页默认先展示 Task，Project 后置。

工作一级 Tabs 为“任务 / 定时安排 / 项目 / 成果”，默认任务列表。任务内以列表/日历切换，同一工具带提供搜索、执行成员、项目、
阶段筛选并写入 URL。列表优先任务、成员、阶段、计划启动和交付截止，尝试次数与内部标识进入详情。执行记录、交付与可选认可归入
同一任务详情，需要管理员决策的事项同时从待我处理进入。成果目录展示全部真实 Deliverable，并单列人工认可 和是否沉淀为文档。
文档详情用单一对象头标明当前版本或历史只读版本，主区呈现该不可变
版本的原文，次区提供版本历史、来源任务与执行入口；版本选择写入 URL，保存交付在同一事务创建文档与首版，资料详情始终呈现已保存正文，不保留空容器界面。
文档、交付、验收标准、用户输入与 Provider 正文必须逐字保留，不经过展示术语的全局字符串替换；中文术语映射只用于系统标签。

2026-09-22 工作重构采用 FullCalendar Standard 作为事件日历，固定经验证版本；优先审查其官方 shadcn registry 组合并通过 CLI
引入适用源码；Owner 随后明确选择官方 shadcn 主题，采用 Forma 暗色组合并映射现有 hutian token。日历布局、事件定位和
周/月/日程浏览复用上游，不自制日期网格。工具栏、筛选、表单与详情复用现有 shadcn/ui。
日历库只负责展示，未来周期由 Core 返回，不能让浏览器重复展开或定时触发业务。默认按日期列扫描的周视图，月和日程视图沿用同一事件；
日期、视图和选中日期进入 URL。日历保留 API 返回的全部真实运行和未来预计，在北京时间同一天内按任务 ID 合并摘要；
摘要保留次数及异常信号，点开列出当天每次预计 / 原运行状态和结果入口。周 / 月每格最多三条，余项通过上游“更多”展开。各次触发仅在摘要详情内查看，不提供主日历逐次展开，不创建运行，不按标题识别业务种类。
周和日程标题明确起止日期，月标题保留年月；周视图使用局部 aspectRatio 收紧无时间轴的空白，仍允许事件内容撑高。
顶部保留时区、任务数 / 预计触发次数 / 实际运行次数；拥挤日期通过上游更多事件入口收起。
计划启动、交付截止和预计周期分别有文字标记，都是时间点，不画虚构执行时长；不裁掉凌晨安排。周/月拥挤时使用上游更多事件入口。
点击日期预填表单；不启用拖拽改期。选中事件先用与列表相同的 Sheet 就地预览，再提供任务或安排的完整详情入口，关闭返回原位置。

2026-10-13 工作交互收敛：任务与定时安排列表使用同一紧凑 Table 组合，标题、状态、成员、时间与固定行尾菜单对齐；支持按状态/阶段或成员
对当前分页结果分组，分组数量明确“本页”，不冒充全部查询的分布。搜索、筛选、分组和分页写入 URL，后退与清除筛选同步搜索输入。
标题或行尾“预览”打开统一工作预览 Sheet，按需重新读取 Core 已授权摘要；读取失败清空正文，提供重试，不复制完整执行、交付历史或编辑器。
Sheet 有 Title、独立滚动正文、完整详情链接、Escape 与焦点恢复；直接打开详情仍保留列表/日历的日期、筛选和分页。
定时安排详情先展示 Core 下次启动时间、规则和成员；已生成期次与尚未生成任务的未来计划分区，后者默认折叠。
带 occurrenceKey 的真实匹配项展开并定位；一期操作收在 DropdownMenu，明确“仅本次”，安排修改明确“修改后续”。
同一对象的提交中与结果未知锁定关闭及切换，原请求组件和幂等键保留；成功后重新读取摘要和日历，不能继续呈现旧许可或时间。
历史成果入口必须携带具体 deliverableId，不得把历史行导向当前交付。此为工作模块局部交互裁决，不扩展 World 全局主题或工作领域模型。

创建表单统一标题、说明、Agent 执行成员、验收标准、执行方式及可选的项目、截止和资料。手动为默认，主按钮按语义显示
“保存任务”或“保存安排”；保存不因运行环境离线禁用。“开始执行”独立操作，启动问题展示真实服务端原因。
重复设置明确时区（默认 Asia/Shanghai）、当地日期/时间、结束条件和延后启动窗口，保存摘要展示下次时间与窗口。
修改后续规则先呈现生效起点及受影响例外，要求明确保留为单次安排或清除。任务详情先呈现目标、标准、当前交付和主要动作，
执行过程与历史尝试折叠。首次启动后不再展示修改原要求的入口；要求修改提交针对具体交付的反馈。

Task completed 显示“已交付”；管理员的“认可交付”独立记录在具体版本上，不改变任务阶段。
当前结果始终来自最新执行；历史交付可查看和认可，不覆盖当前结果。要求修改须提交针对最新交付的具体反馈，重开同一任务。
执行审批在当前沟通回复、任务详情和行为详情中复用同一 Core 请求。用现有 Panel、Alert、Button 呈现具体工具与完整参数，提供“单次允许 / 拒绝”；已过期和结果未知不可批准，不用工具成功状态代替决定投递回执。
待我处理使用同一授权查询的“需处理 / 已处理”与侧栏计数，不把普通交付自动变成待验收事项。
未执行期次只显示实际可用操作；结果未知保留证据和运行环境入口，不提供无证据的确认成功或通用解决。
已处理是实际处置历史，不出现“标已读”“全部解决”。成果回执显示“已交付”及真实入口。

知识库为 World 一级工作面，采用紧凑标题、搜索/项目筛选工具带与连续 Table。目录展示资料名称、来源种类、关联项目、
更新时间和真实检索状态；“导入资料”为管理员主操作，首条路径支持文本/Markdown 原文。导入与更新需预览原文及共享范围，
保存后以 Core 版本和索引回执显示“处理中 / 可检索 / 处理失败”，不得写“成员已掌握”。搜索结果呈现标题、匹配片段与原文入口，
无结果和检索服务不可用分别表达。向量库、外部 namespace、API key 与原始错误不进入普通工作面。
资料详情沿用单一对象头、主区正文与版本选择，保留来源链接、关联项目和管理员“编辑内容”入口。编辑当前导入资料进入
`/knowledge/[documentId]/edit` 独立页面，不用 Dialog 承载持续编辑。主区依次为可编辑的资料名称和正文，次区为“来源与原件”，
不得把导入表单的空文件选择器置于正文之前。来源链接或说明记录外部出处；已保存原件列出文件名、查看和下载，历史原件按版本折叠展示。
更换文件须说明会替换草稿正文，并在已有正文时确认。主操作统一为“保存修改”；只改名称不创建内容版本，正文、来源或新原件变化才追加版本。
资料名称是对象当前展示名；历史正文与已冻结引用不改写。
知识正文按 Owner 于 2026-09-18 的选择使用 Tiptap 3 开源编辑器，工具栏复用现有 shadcn/ui primitive，限定为
标题、强调、列表、引用、链接、代码与普通表格；保留 Markdown 源码编辑入口。加载或切换编辑方式不能自行改写正文。
当前 Core 仍保存 Markdown；超出可往返范围的内容必须明确提示使用源码编辑，不能静默丢失。原件仍按确切版本保存，
未改正文时由服务端保留当前原件，编辑文字形成新正文后历史原件仍可查看，不冒充新正文对应的上传文件。
未保存离开需确认，提交中与结果未知时保留草稿及同一次请求。项目详情的“资料”区域是同一
目录的项目过滤视图，提供正文和知识库入口，不复制资料。现有工作文档保留成果语义，并可从知识库读取同一版本。
会话仅在 Core 返回真实引用时，在该条回复下展示来源名称和版本入口；点击查看确切片段与当时正文。不得把本轮全部候选资料
冒充已引用。临时生成内容与正式引用的显示遵循现有 Message/ActorTurn 边界，刷新后引用仍可追溯。

World 一级“组织”入口使用底部指示线 Tabs 固定分为“成员 / 协作关系 / 职业”。“成员”保持可搜索、可筛选 Table；
当前 World 的 Human Owner 在人类可见界面统一称为“管理员”，保留在成员目录并置于筛选结果首位，以独立“管理员”Badge
和“用户”类型标记；
“管理员”只表达治理身份，必须作为独立 Badge 而不是成员姓名，不推导直属汇报关系、Position，也不新增 Admin 领域对象或
代码别名。正式身份优先显示账号名称，Local 最小身份回退为“我”。成员没有 Position 时，对象头、成员目录、协作关系树与
事实摘要省略职业 Badge/字段，不把“未分配职业”提升为醒目状态；设置表单仍保留可选职业供用户按真实任职手动分配。
成员目录先置顶管理员、再排列 Agent；姓名是详情链接，active Agent 行提供“发消息”，管理员另有直接进入通用设置的“配置”入口。
目录只保留“成员 / 职业与职责 / 成员状态 / 操作”四组信息：可选职业与低强调的当前版本收在姓名下，不为全空职业单独留列；
没有职业时，管理员看到可直接打开设置的分配入口，不重复两行“未设置”。active 在这里显示“已启用”，只表达成员状态，
不承诺 Runtime 可执行。页头使用短说明与内联人数，省略空职业计数；搜索工具带显示结果数及有筛选时的“清除筛选”。
成员搜索与状态写入 URL，切换组织视图、进入详情、切换详情分区和返回成员目录均保留；详情对象头提供成员目录的真实返回路径。
新增成员使用组织下的独立页面，同屏提供必填名称、可选职业与人设，初始为空；成功后进入该成员的详情设置。
Runtime Binding 与 Skill Binding 在创建后的对应设置中维护，不得由 Web 提交伪装成用户选择的默认值。
“协作关系”以可折叠的语义树展示真实直属关系，每个节点只突出成员、可选主职业、成员类型、状态与详情入口；“职业”使用
Table 展示职业名称、单列职业说明摘要、任职人数和 revision；摘要最多两行，名称和操作列保持稳定宽度。新增和编辑职业使用独立页面；不得把三者
做成同权重卡片网格，也不得从职业、创建顺序或 Owner 身份推断不存在的汇报关系。组织树允许多个根，并为尚未建立任何
直属关系提供面向 Owner 的真实空态。直属关系不参与消息响应、会话可见性、任务委派、Runtime/Tool Grant 或权限计算；
每次谁实际处理由会话参与者、`@`、回复关系和服务端 selector 决定。成员详情“设置”增加“组织关系”二级分区，以 Select
维护直属负责人；保存结果回源 Core，并使用全局 toast 表达成功或无变化，冲突继续就地显示 Alert。
组织写入口只对当前 World 的管理员展示：添加或修订成员、职业、直属关系与 Runtime Binding 均由管理员完成；其他成员
可以查看授权范围内的组织事实、成员详情和发起沟通，但不挂载会必然被 Core 拒绝的设置表单或伪只读控件。权限仍由 Core
服务端裁决，Web 条件展示不能替代鉴权。

World 一级“Skills”入口采用 OpenClaw 普通 Skills 的紧凑搜索列表 → 居中详情 Dialog，不再使用大对象页头、
包内容卡片与右侧来源/成员/版本卡片。目录将名称与用途说明合并为可点击的一行内容，尾部只显示当前版本和启用成员数。
详情宽度上限 `60rem`（960px）、高度上限 `90dvh`；固定标题与底部操作，中部独立滚动。标题收拢名称、两行用途说明、
当前版本与启用成员数。包内容采用左侧常驻文件目录、右侧原文的连续分栏：目录按 manifest 相对路径分组，文件夹默认展开并可折叠，
根 `SKILL.md` 优先显示；点文件直接切换内容，选中态清楚，右侧标题显示完整路径和文件大小。左侧独立滚动，长文件名截断并可查看完整路径；
PC 左栏约占 28%，右栏自适应，窄屏改为上方有限高度目录、下方正文，不重新引入包内文件下拉。
该 Skill 局部组合使用现有 `Collapsible + Button + ScrollArea` 与普通列表语义，不新增全局 FileTree primitive 或未实现键盘模型的 ARIA tree。
同层目录和文件统一采用“展开位 / 图标 / 名称”三槽，文件在展开位保留不可见占位；行高、间距和内边距一致，仅子节点增加缩进。
包级工具栏跨越目录与正文两栏，显示文件数和“下载 Skill 包”；下载已保存的精确版本 ZIP，保留全部相对路径、原始字节与可执行位。
该操作不随所选文件改变，也不混入未保存草稿。打包时显示进度状态并防止重复点击，失败就地提示并可重试；
关闭对应包视图取消尚未完成的下载。右侧文件标题只显示所选路径与文件信息，不再挂单文件下载。
根 `SKILL.md` 直接用现有 Textarea 编辑，伴随文件只读，没有并列“阅读/原文/编辑”模式或 Markdown 阅读器。
管理员以“保存修改”追加版本；编辑根文件保留全部伴随文件，
已准入轮次不变。文件选择只隐藏根编辑器，不卸载其草稿和冻结请求；后台刷新按原 CAS 保留脏草稿。

“成员与版本”和“技术详情”默认折叠，后者收纳内部 ID、配置 revision、来源目录及固定提交；成员关联只读，进入成员能力页
才配置启停。只有实际公开 Contract 已有的动作可出现，不复制 OpenClaw 的全局启停、分享、删除、附件编辑或回滚动作。
所有 X、Escape、遮罩、关闭、浏览器后退与弹窗内导航使用同一退出规则：无修改正常关闭并恢复列表上下文；dirty 明确确认
放弃；提交中、等待权威刷新或结果未知时保留原请求组件，不允许卸载。来源更新不得与未保存根草稿并行发起；嵌套导入
结果未知时，父详情也必须保留原请求。选中 Skill 与搜索进入 URL，直接链接、刷新和后退仍使用同一目录与弹窗。

手动创建采用轻量 Dialog 收集标准 `name` 与 `description`，成功后打开 Skill 详情。导入采用轻量 Dialog，
提供 URL、本地文件与本地目录来源；URL 支持 GitHub、ClawHub、Skills.sh，本地文件支持 `.skill`/`.zip`。
选择来源后直接导入，不再选择整仓目录、逐文件预览或显示 hash。使用现有 Field/Input、Tabs、Alert、Button，
上传复用已批准的 Dice UI FileUpload；成功进入已有详情。来源更新明确提示会替换当前内容但保留历史与成员关系，

  当前轮次正常完成且正式回复已读回后才逐条提交下一条；停止、失败、结果未知和刷新恢复后暂停队列，保留内容并提供明确恢复。
  编辑中的队列暂停自动发送。提交中与网络结果未知的条目冻结正文、目标及同一幂等请求，不能改删或换新键重发；
  多条普通待发送消息默认折叠为数量摘要，用户可展开全部条目；单条、编辑中、提交中、失败或结果未知时保持可见，
  暂停原因与恢复入口不被折叠隐藏。折叠不改变队列顺序、发送条件或幂等请求；
- 尚未发送且未进入队列的 Composer 文字与回复对象在本页签 sessionStorage 中按 World、当前 Human 身份和 Conversation 隔离。
  切换会话或刷新可恢复同一范围的草稿；只读历史不执行恢复或写入，不用缓存覆盖用户已经输入的正文、附件或回复对象。
  恢复时原回复消息不在当前授权消息记录中，保留草稿并阻止发送，明确提示重新选择回复对象或取消原回复；
  不把回复静默改成普通消息。附件不持久化，存在附件时说明切换会话后需要重新添加；存储不可用时明确提示先复制正文。
  草稿恢复不触发 Message 准入、ActorTurn 或后台发送；
- Composer 的“停止”只作用于明确的当前执行，同时暂停待发送队列，不清空草稿，也不在停止后自动启动下一条。
  沟通中的停止按上述 Codex 局部交互直接提交，不额外弹确认；先显示正在停止，等待 Core 权威终态，不把取消请求回执当成已停止。
  消息提交请求尚未返回时临时禁用发送；提交前已知无法引导时自动排队；引导提交失败或结果未知时不得静默转换为新一轮。
- 多成员 Conversation 的 Composer 必须复用 assistant-ui trigger popover 提供 `@成员` 选择；候选只展示当前会话中的
  active Agent。输入区使用 assistant-ui Lexical Composer，把选中成员呈现为可聚焦、可整块删除的 Mention chip；弹层
  必须支持 `ArrowUp`/`ArrowDown` 移动可见高亮、`Enter`/`Tab` 选择和 `Escape` 关闭，鼠标与键盘共享同一选中状态。
  同一条消息可连续选择多个 Agent；每个选中项保留独立 chip，提交时按 Actor ID 去重，不能把后一次选择覆盖前一次。
  中文正文后可直接输入 `@` 触发，不能强迫用户额外插入空格；邮箱式 ASCII 文本不得误触发。
  选中后底层仍保留可读的 `@显示名`，发送时把对应 Actor ID 作为服务端 selector 的 client hint。正式 Human Message
  在 Markdown 正文节点内使用 assistant-ui Directive Text 显示 Mention chip，但只把 Core 回传的 `MessageAddressing(explicit)` 作为可确认身份；
  未确认、已失效或无法唯一匹配的文本继续按普通正文展示，不能由浏览器重新猜测 Actor ID。Mention chip 使用低对比
  Accent Surface、单个 `@` 前缀和正文同字号，不做高饱和标签云。裸文本、客户端 hint 与重复显示名都不能成为最终唤醒
  权威；服务端仍需校验参与关系、Actor 状态、响应规则、busy/cooldown 与共享 budget。消息“回复”必须保存
  `replyToMessageId`，Composer 显示当前回复对象且可取消。Human 主动回复始终显示被回复的作者与正文摘要；Agent 正式
  回复若紧邻其目标 Message，或属于一组连续且全部回复同一条 Human Message 的多 Agent fan-out，则由消息组直接表达关系，
  组内所有回复一致省略重复引用。新的 Human Message 或回复目标变化会结束该组，之后的跨组回复才显示引用上下文。该视觉
  折叠不能删除 Core reply 事实；服务端 selector 仍以可验证 reply author 优先于 mention hint，UI 不按到达先后猜测回复归属；
- 消息中的回复引用整行可点击，也可键盘激活；以 Core reply Message ID 定位当前消息流中的原消息，滚动到可见区域中部、
  转移焦点并短暂低对比高亮。用户偏好减少动态效果时即时滚动；不改变消息顺序、回复对象或 Composer 草稿；
- Human 在同一条消息中显式 `@` 多个 Agent 表示有意让每位成员分别处理，不是让系统选一个代表。Core 为每位通过
  响应规则与共享 budget 的目标创建独立 ActorTurn；不同 Agent 在各自 Runtime Session 中可以并行执行，正式回复按
  WorldEvent 发生顺序分别进入消息流。界面保留成员身份与独立回复，不合并为一条“综合答案”，也不显示为答案版本；同一
  Agent 在同一 Conversation 内仍严格串行。无定向 Channel 消息继续只选择最多一个自动响应者，不能因会话中有多个 Agent
  就默认产生多人抢答；
- Core Message 是不可变沟通事实，普通已完成回复只提供复制、导出等不改变事实的操作；不得展示 assistant-ui 的
  BranchPicker、Reload 或已发送消息 Edit，也不得用 `1/2`、`2/2` 把多个 ActorTurn 或 Agent Message 表现成答案版本。
  只有失败、取消、Provider 已完成但没有正式 Message，或创建 RuntimeInvocation 前因 `RUNTIME_UNAVAILABLE` /
  `RUNTIME_NOT_CONFIGURED` 收口为“未开始”的 ActorTurn 才可在错误状态旁显示“重试任务”；它创建新的受治理 ActorTurn，
  不覆盖旧证据，也不是对成功回复的“重新生成”。需要审批、治理输入或结果对账的 waiting/blocked 不提供重试，继续使用
  对应的 resume/reconcile 路径；
- 聊天头固定展示会话标题、类型、参与成员与是否会触发 Agent 回复；只有当前 Human 与一位 Agent 组成的双人 Direct/Session
  使用紧凑成员头部，突出姓名、可选职业、参与者可见范围与同成员新会话入口，成员详情和记忆入口收在会话选项中。
  多人 Session 即使只有一个 Agent 也保留参与者摘要与响应说明，不以 Agent 数量推断二人私聊。不可用成员继续显示真实提示。
  消息区独立滚动，Composer 固定在工作台底部，
  页面滚动不得把输入区带走。参照 Codex 任务聊天的信息机制，已有消息从滚动区顶部按时间连续展开，短历史不得整体沉到
  Composer 上方形成大面积顶部空白。消息正文与 Composer 共用约 48–52rem 的单一阅读列，并保持同一左侧起点：用户输入
  使用低对比 Surface 提示块，Agent 回复使用带成员身份的无框正文流；不得使用左右对话气泡让视线在宽屏两侧往返，也不能
  让 Composer 扩展成远宽于消息的横条。连续 Human → Agent 回合以紧凑间距形成任务记录，成员身份、状态与消息操作属于
  正文的次级信息，不能把每条消息拆成孤立的大卡片。Human 提示块不得额外缩进；Agent 的回复动作必须与复制、更多操作
  位于同一个 ActionBar，不得用脱离消息 paint box 的独立浮层覆盖 Mention 弹层；Composer footer 建立明确的浮层层级，
  Mention popover 始终绘制在历史消息和消息操作之上；
- Conversation 内同一 Agent 的 `queued`、`running` 与需要治理或结果对账的 `waiting` Turn 保持消息顺序；但在创建
  RuntimeInvocation 前因 `RUNTIME_UNAVAILABLE` 或 `RUNTIME_NOT_CONFIGURED` 收口的等待只代表该次回复未开始，不能继续
  阻塞后续消息。后续消息必须重新按当时的 Runtime 可用性独立裁决，Web 不得把旧等待误显示成新一轮仍在生成；
- 当前用户位于最新消息时，发送与流式回复使用 assistant-ui 的底部锚点和自动跟随，不能把新一轮用户消息强制锚到
  视口顶部；用户主动上滚回看后停止自动跟随，并保留“滚动到最新消息”入口。Provider 返回的 reasoning summary 与
  Tool 事件使用 Beautiful UI Thinking/Tool Chips 组合折叠呈现；没有真实 summary 事件时不显示空的 Thinking，也不得把内部状态、
  Token 数或模型原始思维链伪装成可读推理；
- 同一回复的摘要与工具记录统一收进一个执行过程折叠入口，默认收起；入口显示真实处理耗时与工具数量，用户可随时展开。
  从生成中转为已结束时，未被用户手动操作的过程收起；用户已手动展开或收起的状态保持不变。摘要与工具不再各占一张默认展开的卡片，
  过程详情限制高度并可滚动，避免持续增加的执行日志挤走正文。折叠入口可补充真实当前工具动作、工具失败数与结果未确认数，
  不根据输出文本、演示计时器或后续成功推断整轮成功；先前工具异常仍保留。工具按 Provider 的 commandActions
  区分读取、搜索、列目录与命令，连续文件检查可以分组，展开显示实际命令、结果、退出码与耗时。参考 ZCode 固定提交
  `aac4755666d09fdcd70272fcf063c077a639015f` 的分类、折叠与详情交互，继续使用现有 assistant-ui、Beautiful UI 和 shadcn/ui；
  不引入 ZCode 客户端或业务状态。此为 hutian 的产品组合，不宣称完整复刻 Codex；
- 执行审批按 Core 状态显示：当前会话待决定、决定待送达或结果未知的审批集中在 Composer 上方的底部停靠区，原回复只保留简短状态与定位入口；
  普通输入框及草稿保留，审批不把发送文字变成批准。每项标明成员与所属轮次，多个请求可逐项展开，停靠区限制高度并滚动；
  决定只对 pending 请求开放；原生请求显示其真实选项名称与作用范围，以冻结 optionId 提交，不能压成统一允许/拒绝。结构化提问在同一停靠区使用既有 Input、Select、Checkbox，保留问题/说明/必填与秘密字段语义；历史二值 Driver 的单次允许仍须 canAllow 明确支持。决定送达前仍留在停靠区，结果未知只提供核对；
  已送达或过期的审批进入同轮执行过程，默认收起，实时结束与重新打开会话采用相同规则。审批先呈现具体操作，完整参数按需展开；
  已送达决定不代表工具执行成功。历史过程未读取时，耗时与“查看执行过程”合并在同一左对齐入口；工具摘要使用紧凑文字行，
  长命令省略并可展开完整内容，输出限制为约五行高度且可滚动，正文不被原始 JSON 或长输出挤走；
- 正式消息保留 Core 返回的 WorldEvent 发生顺序，生成中的回复附着在触发消息及其连续正式回复之后；正式回复出现时按
  ActorTurn 关联去掉对应临时回复。消息排列不使用 `createdAt`、执行开始时间或客户端时钟重新排序，执行时间仅用于活动计时；
- ActorTurn 的处理耗时由独立的 turn activity data part 提供：有执行详情时放在统一折叠入口，无详情时单独显示；
  运行中显示“正在处理”，结束后显示“已处理 x”，正文前保留横向分割线（Divider）。耗时不由 Thinking 或 Reasoning 推断；完成态必须从
  Core ActorTurn 的 `started_at/settled_at` 恢复，不能只存在于一次前端流式会话中，也不能用客户端定时器伪造历史事实。
  `waiting|blocked` 已经离开主动执行态，即使尚未写入 `settled_at` 也必须停止活动计时，并由对应等待/中断提示接管；
- 聊天头在存在真实关系时展示关联 Project，并提供“本轮上下文”入口；上下文使用 shadcn/ui Sheet 从右侧按需打开，
  只展示 API 已拥有的 Project、Conversation、参与者、消息数量与服务端冻结边界，不猜测 PerceptionSnapshot 的具体内容。
  完整 Message 历史与本轮模型输入必须在文案和信息层级上明确分离；没有摘要继承或输入明细 Contract 时不得展示假按钮；
- 正式 Agent 回复不再常驻单独的记忆按钮；在已有消息 ActionBar 的“更多”菜单提供“查看本轮上下文”，以 Sheet 按需读取该回复的 Core 记忆冻结输入和动态读取回执，展示当时原生类别、正文
  和成员记忆管理入口。明确“提供给模型，不代表一定采用”；与知识库的“引用资料”分开。加载中、读取失败、明确未带入和
  历史未记录分别表达，不根据当前记忆列表反推，也不把 Runtime 自身的记忆或完整上下文冒充为已枚举。动态读取按 Core 输入回执展示实际返回内容和来源，明确区分“待交付 / 已交付 / 交付未确认”；已交付也不等于模型采用。关闭后清理读取结果，
  再次打开重新授权读取；无权与不存在使用相同提示，不展示隐藏条目数量。
- 聊天中的真实资料引用采用 Beautiful UI Context Cards：默认收起为“资料数 / 片段数”摘要，资料数只按 Document ID 去重，
  展开仍保留每条原引用序号、标题与真实片段，不按相同标题或同一资料合并、删除引用。卡片可裁剪片段预览，但原 Sheet
  必须提供完整 quote 和原 DocumentVersion 链接；完整资料按需经既有权限读取，不预取正文，不反推模型完整上下文或 token 比例。
  引用 Sheet 关闭后焦点回原触发按钮；折叠后隐藏卡片操作不参与键盘导航。其他工作页面的引用按钮不随聊天组合一并替换；
- 空会话使用一个无边框的紧凑下一步提示，不放大面积欢迎卡，也不重复顶部通知。Agent 会话在输入为空且可编辑时可提供
  “梳理目标 / 分析问题 / 打磨内容”等起手建议；选择只填入可编辑草稿并聚焦输入框，不自动发送、不覆盖既有输入，也不宣称
  成员具备未确认能力。仅用户参与的会话继续说明需要对方本人回复；
- 活跃目录底部提供低强调的“已归档”入口；使用 shadcn/ui Dialog 与连续 Item 列出 Core 返回的 archived Conversation，
  归档只收起会话，恢复必须调用 Core lifecycle API 并等待权威列表刷新，不把归档表现成删除；
- 移动端在“会话目录”和“当前会话”之间切换，当前会话提供明确返回入口，不把两栏压成横向溢出；
- Core 尚未提供某项生命周期、未读、最后消息或搜索结果时，不展示无效动作或伪造状态。

### 6.18 世界线与平台工程诊断

世界线突出自然语言摘要、事实类型和发生时间；opaque cursor 只用于续页、补拉与诊断，不在普通列表中作为产品内容展示。
诊断一级入口统一命名“日志审查”，一级 Tabs 顺序为“执行记录 / 响应判断”，默认执行记录。URL 保存视图、关键词、成员、时间、状态、来源与分页；详情返回保留查询位置。
执行列表以消息/任务摘要为主标题，显示成员与来源、执行状态、耗时、检查发现和时间；不再用“调用 Runtime”和行动数量代替事情。工具带复用 Input、Select、Button，按服务端授权结果筛选。响应判断列表显示消息摘要、作者/会话与处理结论；资格与完整规则进入详情，未知规则不能推断没有响应。
详情阅读顺序为事情与来源、实际结果与检查、执行过程、按需步骤证据。对象头直接显示触发内容和来源入口，不重复判断长说明。执行状态、检查发现和证据完整性分别表达，无 Runtime 时模型检查不适用。时间统一使用 Asia/Shanghai（UTC+8），服务端与客户端一致。

日志审查、Trace、ActorTurn、Runtime、部署与基础设施诊断属于平台工程工作区，默认面向平台工程师。它可以直接展示
内部 ID、枚举、JSON、Token、模型、Driver、协议、Endpoint 与原始错误；但必须执行 World 隔离、可见性、Secret 脱敏和
私聊保护，平台角色不能自动绕过内容权限。完整 Runtime prompt 默认不随页面读取；仅在展开证据时返回已保存、通过当前来源权限校验并遮盖内部凭证的文本，标注保存范围和完整性。未保存时不得用当前 Skill 或会话历史反推。Runtime 详情复用现有 definition-grid 展示提交后总耗时、接单等待、准备与执行阶段；
空时间显示未记录，重试的接单等待标明包含此前尝试。Started 是 Core 准入，不能标成模型首 token；Token 区显示实际计数派生的缓存比例，
区分缺失与零命中，各次请求合计不冒充单次上下文。这里只扩充既有详情字段，不新增图表或全局组件。
所有 ActorTurn 复用“单一对象头 + 完整执行树 + 步骤详情”的页面骨架，
不按 Action key 或沟通、工作、交付、审批、等待分别复制布局。主区只保留一种完整阅读方式：以“收到触发、做出决定、
执行行为、形成结果”为阶段父节点，把已经通过可见性裁决的 trigger、candidate、行为节点、ActorAction、
ActionResolution、Runtime/Tool Invocation 和权威结果组合为“阶段 → 用户步骤”两层。页面不能把底层因果链
逐层等比缩进；行为节点按持久化 node path 形成的路径、Action 与 Resolution 的归属、Invocation 来源和 Runtime final
产生后续 Action 的关系仍须完整保留在步骤顺序和 Sheet 详情中。执行树默认展开全部两级，用户可以收起或重新展开阶段；
折叠只改变当前视图，不删除、筛选或改写记录。点击用户步骤后，使用 shadcn/ui Sheet 从视口右侧直接展示该步骤合并后的
完整证据，详情独立滚动并提供上一条/下一条；关闭后保持执行树原滚动位置。
阶段行只负责组织和展开/收起，不打开详情，也不计入 Sheet 的“第几条 / 共几条”；该计数和上一条/下一条只遍历真实用户步骤。
步骤详情不能代替、筛掉或永久隐藏执行树。页面只保留一个顶层 `main` 地标；Sheet 的长内容区必须具有可访问名称、可由键盘
聚焦并在视口内独立滚动，不能依赖页面滚动把详情带回可视区域。

执行树之前以默认收起的紧凑区域展示“本轮工作方法”：有冻结 Skill 时按顺序列出名称、版本、简介和进入 Skill 详情的入口，
并明确后续发布、停用或移除不改变本轮；冻结集合为空时只用一行说明本轮未启用 Skill，结构化快照缺失时说明历史证据不足，不能用
当前成员绑定反推。完整 `SKILL.md`、instructions、metadata、内部 ID 与 hash 不进入该摘要；ID、binding revision、profile
hash、resolved-set hash 与各版本 content hash 只进入默认折叠的技术证据，`allowed-tools` 不能显示为权限。

执行树外层必须占满诊断面板，不能把 `max-width` 加在整棵列表上，形成像常驻右栏缺失一样的半屏空白。阶段行、步骤行、
hover 与选中背景都铺满可用工作面，并统一使用“状态/展开标记 + 可换行正文 + 右对齐状态文字”的三栏网格；正文列必须
`min-width: 0`，其中的标题和说明块保持约 `52–64rem` 的可读上限，状态列固定在整行尾部作为扫描锚点。超宽屏增加的是
正文与尾部状态之间的自适应间隔，不是无语义的保留面板。阶段的“n 个步骤”是低强调计数文本，不使用与业务状态相同的
Badge。时间使用 tabular numerals，元数据不强制英文大写。

左侧圆形标记只表达权威生命周期：完成/通过使用 Accent check，排队/执行/等待使用状态时钟，失败/阻塞/拒绝使用
Danger 警示，尚未产生终态的普通事实使用 Neutral dot。用户当前在 Sheet 中查看哪一步属于本地阅读状态，只通过
`Surface Active + Accent` 左侧信号线表达，不改变圆形标记或业务状态 Badge。状态文字按对象语义使用一致的完成式文案，
例如“已记录 / 已比较 / 已选择 / 已通过 / 已完成 / 已写入 / 已形成”；不得在同一条成功链中混用无上下文的“成功”、
“已接受”和“已完成”来表达不同层次，也不能把阶段计数、当前选择和业务终态都做成同一种绿色胶囊。

“用户步骤”不是一行数据库记录，而是用户可识别的一次完整操作。一次操作的 ActorAction、按 sequence 追加的
ActionResolution，以及 accepted Resolution 直接创建的 Runtime/Tool Invocation 必须合并为同一个主树步骤；Invocation 的
queued、running、completed、failed、canceled 与 outcome_unknown 只是该步骤的状态生命周期。只有 Runtime/Tool 终态之后
新构造、需要再次经过 RuleResolver、并可能独立等待、拒绝、失败或创建新权威事实的 ActorAction，才形成下一个用户步骤。
无法用权威 result reference 证明归属的历史 Invocation 不得猜测合并，保留为独立诊断记录并说明关联缺失。

沟通链必须按上述边界表达，不能把系统边界伪装成人类聊天动作。做出决定阶段把 `conversation.compose` 表达为业务意图
“回复消息”；执行阶段把该 ActorAction、Resolution 与其 RuntimeInvocation 合并为“调用 Runtime”，状态和耗时随 Invocation
更新，不再把“提交给 Runtime”和“Runtime 已返回结果”拆成两个并列步骤。Runtime final 后新构造的 `conversation.send` 及其
Resolution 独立显示为“写入会话”，表示 Core Message 已原子创建。形成结果阶段再展示正式回复正文。主树不得使用“生成回复 /
发送回复”，因为正文由 Runtime 返回，而 `conversation.send` 是 Core 事实写入，不是向外部聊天系统再次发消息。
失败、blocked、waiting 与 outcome_unknown 只改变节点状态、默认定位和恢复操作；即使自动定位问题节点，其他分支和
前后上下文也必须保留。不再提供与层级树重复的“精简过程 / 全部事件”切换。

直接决定显示来源与原因；不展示候选分数、策略版本或行为树节点。
Runtime 节点必须把“hutian 本轮新增输入”和“Provider 报告的整轮 Token”分开：展示当前用户有权查看的触发消息、
Provider session 是首次建立还是续接、冻结上下文数量，以及 Provider 返回的 input/output/cache usage。`inputTokens`
表示 Provider 对该模型轮次统计的完整输入，可能同时包含 hutian 新增文本、已恢复的 Provider session 历史和 Provider
自身运行时指令；Provider 未提供逐来源 Token 时必须明确写“无法拆分”，不能按字符数伪造占比。完整
PerceptionSnapshot、ActorAction input、内部 ID、hash、内部路径或整段原始 JSON 放入默认折叠的“技术证据”；原始
Prompt 只有在已经持久化、通过同一可见性裁决且不含 Secret 时才可按需展示，不能根据当前状态反向猜测。普通列表仍不让
内部枚举压过业务标题。

### MVP 交办与辅助读取（2026-09-24）

新任务默认“立即交办”，只要求标题和执行成员；说明、完成标准、项目、资料与回报位置在可选折叠区填写，打开后才读取辅助列表。“仅保存”与定时仍是明确选项。
实时状态只说明连接是否正常，订阅成功或新通知触发合并刷新，不显示“世界线已补拉”。归档 Dialog 打开才读取列表，侧栏不为计数提前取全量。代码入口使用当前页摘要，面板打开才读取单次 patch；辅助读取失败就地展示。任务当前交付始终读取，执行/交付历史由 history=1 打开。
任务与单次执行详情只观察本页 queued/running Turn，复用 AG-UI 并在终态回源 Core；与 Worldline 共用合并刷新，退出页面取消观察，历史终态不订阅。任务只有可编辑时才读取成员和项目目录，执行观察不改写交付、重试资格或未提交表单。

### 日志证据补充约定（2026-10-14）

工具步骤先展示参数与可读返回，再提供回执、时间和原始 JSON；没有持久化的耗时写未记录。Runtime 步骤展示当时请求的模型、思考等级、服务档位、沙箱和审批配置，未获执行端确认不能标注实际生效。概览只保留关键耗时/缓存/输入数字并链接相应证据，不重复完整详情。输入字符数与累计 Token、未缓存 Token 不能互换，Token 计数不映射成未经采集的原文片段。
