## 修正此前判断

1. “结束只收工具明细，进度永久保留”错误。整轮活动和工具组有独立折叠。
2. “结束必定隐藏一切过程”过度概括。常规路径在最终回答开始后允许自动折叠，用户保留展开与其他视图条件可改变结果。
3. 最终回答开始和运行完成不是同一事件；完整完成操作栏不应由首个 final 文本或动画计时器触发。
4. 审批成功不是工具成功，更不是整轮完成；拒绝一项操作也不必然结束整轮。
5. “停止/失败后重新来一次”不能被笼统包装成原地继续，已有外部修改不会因停止自动撤销。

## 状态与事件约定

运行状态、连接状态、待决请求、消息投递和展开状态分别保存，避免一个 `completed` 布尔值控制全页。

- 正常：草稿 → 发送中 → 已接收/处理中 → 答案输出中 → 确认完成。
- 审批：处理中 → 等待决定 → 决定提交中 → 执行端确认 → 继续工作 → 工具结果 → 答案 → 完成。
- 提问：处理中 → 等待回答 → 回答提交中 → 接收后继续；非阻塞问题不改变其他独立工作的运行状态。
- 停止：活动状态 → 正在请求停止 → 原运行确认 interrupted；断连时保持停止结果待确认。若完成和停止竞态，以原运行最终回执为准。
- 出错：可重试工具错误 → 当前运行继续；整轮 failed → 保留历史。继续工作另开一轮并引用已完成部分。
- 断线：仅改变连接可信度；恢复时核对原消息/运行身份与最新回执，不能产生第二次派发。
- 排队：正常完成后顺序派发；H 决定停止/失败后暂停队列，用户可移除或明确开始。接收失败的补充不静默当成新一轮。
- 等待授权/回答时，输入框仍能保存其他草稿并排下一轮；审批/提问使用各自响应控件，普通文字发送不擅自代替授权。

## 原型与正式接入界限

候选原型 `hutian-chat-reviewed.html` 位于当前聊天的 visualization 目录。外部“走查场景 / 下一步”模拟执行端事件；里面的发送、停止、审批等按钮只发起请求，必须走到后续确认步骤才出现结果。没有调用模型、修改文件或申请真实授权。

所有示例资料、时间和结果均为原型数据。用户输入只在原型本地状态中使用。这里验证的是交互衔接，不是后台消息队列或恢复能力。

本轮已核对 Dock 的消息 phase、补充、取消、权限请求与原运行查询契约：主要缺口是宿主桥接，另有 partial_answer 与独立提问／resolved 元数据的适配需要确认。实际送达与端到端表现尚待集成验收；不支持的能力必须按事实降级。Matrix 仍是消息权威，Dock/原生 Harness 是执行权威，hutian 不建立第二套执行事实。正式界面继续复用 assistant-ui 与现有 primitive。

## 本地候选原型走查记录

2026-11-15，Chrome 打开本机预览页，操作 iframe 内控件观察结果。以下是手工走查记录，没有添加自动化测试或 fixture：

- 完成态：整轮收起后活动不在正文中，最终回答保留；重新展开后内层工具明细开合保留。
- 正常发送：发送中、运行中、回答中、完成分别推进；回答中未提前出现完整完成操作；手动展开优先。
- 审批允许：提交中、送达后保存、工具写入确认、继续工作、回答、完成分开；确认保存后文件才出现，并可预览。
- 审批拒绝：决定提交后继续处理，最后返回文本，不出现被拒绝写入的文件。
- 提问：自由输入草稿在模拟离开／返回后保留；提交后等接收才继续。
- 补充：先待接收再确认，保持同一轮；排队提交后可见，停止确认后队列暂停，明确开始才创建下一轮，旧记录保留。
- 错误：工具重试回到当前运行；整轮失败后继续建立新一轮并保留旧失败记录。
- 连接中断：直到模拟核对回执才恢复原运行；消息发送失败可重试；直接回答场景没有空的过程折叠。
- 群聊：当前工作明确属于墨菲，另一角色不自动启动；停止控件指向墨菲当前工作。

已查看浏览器渲染结果；没有验证真实剪贴板内容、全部窄屏／键盘导航、真实附件上传、网络恢复、授权失效和多角色并发。示例回复是固定研究材料，不是模型根据任意输入生成；外部走查按钮用于手动模拟事件。通过本地原型走查不计入正式功能验收。
