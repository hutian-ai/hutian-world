## 可用入口与行为

打开 http://127.0.0.1:3340/schedules 。可在日历与列表浏览、创建、编辑后续、暂停 / 启用、删除或立即运行任务，并查看实际运行与原消息中的交付结果。

- 时间支持一次性、每天、每周、每月、每隔 N 天，以及同一日多个执行时间；明确当地日期、时间、IANA 时区、结束日期和允许延后启动窗口。
- 下次时间和预览由业务 API 计算；页面不负责计时或产生业务执行。时区计算沿用原 hutian 的 RRULE 浮动时间与 Temporal 转换方式；夏令时缺失的当地时间跳过，重复时间选择较早的一次。
- 安排固定选择角色、交付会话、电脑和 Harness。成员默认 Runtime 改变不自动迁移该安排；每次派发仍检查角色、房间参与关系与当前 Runtime 可用性。
- 知识、记忆沿第 4 段的合法范围读取。定时工作采用任务执行模式，可按明确授权使用原生工具，但不修改原生模型、思考强度、工具或审批权限。
- “立即运行”是独立手动期次，不改自动周期；保存本身不会立即运行。一次性安排触发后不再产生未来期次，原运行继续处理。
- 静默选项用于休市、尚未到报告节点或已交付等源规则明确要求无需新结果的情况。宿主保存跳过状态，不发空报告；故障不能冒充成功。

## 数据与恢复边界

增加显式 migration 创建 `scheduled_tasks` 与 `scheduled_runs`，由 hutian 保存周期、工作要求、范围引用和每一期原消息 / 原运行 / 原回复的关联；不复制 Matrix 回复正文、Dock 回执、记忆或行情账本。源码仍在同一仓库内，没有新建任务平台或服务。

业务 API 每 15 秒检查持久安排，事务锁和期次唯一约束防止同一安排同一计划时间生成重复期次；运行使用短租约。每一期冻结当时的安排。发送消息用期次 UUID 作为 Matrix transaction ID，消息确认后先持久保存 event ID，再请求执行；恢复只沿原消息与原宿主 job / Dock receipt 观察。网络结果未知不换编号或复制新任务。

同一安排已有未结束运行时不重叠执行，新一期记录错过；宿主仍全局串行处理，不宣称新增并发能力。服务停机超出允许启动窗口时记录错过并跳到下一期，不补发一串过期日报。暂停只阻止后续触发，不取消已生成或在途运行。业务 API、Web 服务、Matrix 宿主与所选 Runtime 需要可用；关浏览器不影响后台，关机不保证准点执行。

所有来源仍按本机可信单创造者边界管理。运行结果通过 Matrix 原 event ID 按当前房间权限读取，超过最近消息窗口也可按原 ID 核对。对已读副本的撤回、跨创造者身份、分布式高可用和任意在途迁移不在本段。

## 股票只读审批与报告附件

原 CLI 的非交互输入会拒绝原生审批，实际富途只读交易日历请求因此被取消。hutian 现在用已安装 SDK 的公开 `ServerClient` / 回调契约执行任务，不修改 Dock 源码、原生权限或模型配置。专用任务客户端按运行、设备和 daemon 关联原生工具进度，再与原生审批的 toolCallId 核对；仅匹配所选电脑、`futu` 服务和本次股票研究明确需要的精确只读方法时，响应原生 `allow_once`。不依据模型文本、工具名模糊前缀或选项位置推断授权。账户、交易、修改自选、无法关联和未知请求均拒绝。

可允许的方法还受源码中的只读目录约束；本机私有 `.local/task-approval-policy.json` 只能选择该目录的子集，不能通过 `quote_*` 通配符扩大。凭据仍由原生 MCP 保存，没有搬到 hutian。任务客户端被墨菲的独立私有宿主配置引用；普通文本聊天及其他助手原配置保留。单次审批与交付事实保存在原宿主记录，不另建原生执行账本。

报告结果按原 Matrix event 读取，并可打开原交付实际引用的 Markdown / JSON / CSV 附件。`report-files.json` 仅连接已选本机 Runtime 的原 reports 目录；不扫描目录，不能读取回复未引用的文件或跳出该目录的 symlink，读取前仍核对当前会话权限。附件展示当前本机文件，不承诺是不可变历史快照，也不承诺远端电脑的路径可直接读取。
