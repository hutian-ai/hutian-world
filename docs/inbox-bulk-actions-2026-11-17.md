# 收件箱行内操作与批量处理

第 7 段增量。2026-11-17 用户实际试用通过，并授权提交与推送。打开 `/inbox` 即可使用，无须逐条进入工作详情才能标记通知。

## 当前用法

- 每行左侧复选框选择通知；标题与正文继续打开工作。勾选不触发导航或已读，支持键盘 Space。
- 列表顶部提供三态全选。全选只包含当前筛选下已加载的通知；列表达到接口上限 100 条时明确说明范围。后续到达的新通知不会自动加入选择，切换筛选清空选择。
- 选中后显示数量、取消和批量操作。「待处理」主操作是标为已处理，「全部／未读」主操作是标为已读，其余操作进入更多菜单。按钮显示实际适用数量；只有已结束的失败／错过记录可手动标为已处理。已处理与已读仍相互独立。
- 行尾提供直接标为已处理或切换读状态的快捷按钮，更多菜单提供读状态、重新运行和任务与历史。多选期间禁用单行操作，避免作用对象混淆。
- 保存后显示实际成功与失败数量，仍在当前列表的未完成项保留选择。通知提示提供最近一次成功操作的撤销入口，显示 15 秒；撤销恢复原标记，不改变运行结果。
- 重新运行仅支持单条，创建新 occurrence。批量重跑、跨页全选和新的筛选系统不在本轮范围。

## 实现边界

`hutian-design` 提供通用 `SelectionBar`、Checkbox 三态和已有 Item、Button、菜单、Tooltip、Sonner。新增独立文档示例，示例仅使用演示数据。修正 Checkbox 半选图标为横杠。

Web 管理当前选择和操作组合，顺序复用原通知标记接口，收集逐项结果；API 保持访问范围及通知版本核对。标记接口返回原值、写入值和 PostgreSQL 行版本，撤销仅在原状态版本、字段值和行版本仍匹配时执行；后续读状态或处理状态变化会使旧撤销失败，避免覆盖。没有新增数据库表或迁移。

Vite 统一 `sonner` 解析，避免消费应用的 toast 和设计包的 Toaster 持有两份通知状态，导致成功提示／撤销入口不显示。Web 继续通过已有原子构建发布静态资源。

## 实际验收

使用一个未启用、无 Runtime 的临时安排，产生 5 次启动前失败记录（包括行尾重新运行），未执行模型或重跑股票日报。验收后临时安排保留历史删除，验收通知标为已读和已处理。其他安排定义逐项比较一致。

- 真实浏览器：键盘勾选、半选／全选、勾选不改已读、批量处理／读状态及撤销、行内处理、混合选择的适用数量、筛选切换清空选择。
- 人为中断一个通知标记请求，其余请求仍写入真实后端；确认部分成功反馈、失败项保留选择及重试。不是伪造成功响应。
- 390px 窄屏选择、批量处理和撤销通过，无页面横向溢出；复选框保持正常尺寸。
- 工作详情手动标为未读后，跨过详情轮询周期仍为未读。
- 通知发生后续写入时，旧撤销被 API 以冲突拒绝；没有覆盖新的状态。
- 行尾重新运行建立新记录，原失败历史保留。
- 设计包、API、contracts 和 Web 必要类型／构建检查以及相关 lint 通过。未新增测试文件、框架、fixture 或 CI。

## 本轮服务中断

加载 API 更新时发送 SIGTERM 后，旧进程停止响应但没有退出，短暂导致浏览器无法建立会话。确认无活动定时执行后，通过现有 launchd 服务强制重启 API 恢复；Web 与聊天宿主未重建。随后真实浏览器重新建立会话并成功加载收件箱，三个服务健康。此次恢复不等于已修复 API 关闭流程的根因。
