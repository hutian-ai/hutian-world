## 使用路径

- 创建任务只选择负责成员、工作要求和时间；名称可留空自动生成。成员页可查看该成员的任务或直接创建，日历日期仍可预填一次性任务。
- Runtime、模型和推理等级继续归成员。创建 occurrence 时冻结当时的成员绑定，后续成员修改不改变已经排队或运行中的快照。没有配置时本次明确失败，收件箱提供成员设置入口。
- 每次新运行自动建立独立双人工作对话，稳定 Matrix 房间别名以 occurrence ID 去重。普通沟通目录隐藏这些自动对话；任务详情按任务组织运行历史，收件箱和日历进入同一工作。
- 收件箱提供全部、未读、待处理。完整正文、过程、原生授权和追问复用现有聊天组件与接口。通知表仅保存运行引用、提醒类型、已读和处理状态，正文仍由 Matrix 保存。
- 原生执行失败、错过启动、待授权和状态待核对均有对应事项；成功回答有结果提醒。静默无更新保留日历和历史，不新发提醒。原生正常回答中的业务受阻说明仍忠实显示，平台不按关键词推断报告成功与否。
- 已读不会解决失败或批准权限。只有已结束的失败／错过记录可手动标为已处理，原状态不改变。重新运行创建新记录，原失败保留。原生已拒绝或请求已过期时，不能通过通知按钮追认授权。

## 技术与数据边界

沿用 API 内 DBOS 时钟与协调、Matrix 消息、Dock 原生执行。Web 仍是纯静态前端；没有新仓库、调度服务或第二份消息账本，没有应用工具白名单。

任务输入移除 Runtime 和目标房间。旧定义中的这些字段作为历史数据留存，但不再用于生成后续运行；旧 occurrence 快照、原生运行与原房间关联保留。原五个股票任务的 ID、提示、周期、成员、启用状态和来源不因这次调整重建。

新增显式 migration `ScheduleInbox1794840000000`。旧结果导入为已读，避免一次性弹出所有历史报告；旧失败没有被自动声称已处理。新通知以 occurrence 为唯一引用，状态变化复用同一通知，读取与处理使用版本核对，重启不重复插入。

通用执行桥默认要求在聊天正文交付结论，仅实际文件任务提供文件；不再要求普通报告额外生成文件或 ZIP。只有最终回答链接了本次输出目录的文件时才尝试原文件回流；无文件的文字回答不会进入目录收取路径。此前历史 ZIP 和大附件传输问题没有被迁移或宣称修复，既有文件记录保留。
