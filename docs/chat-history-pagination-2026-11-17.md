# 聊天历史自动分页 · 2026-11-17

## 范围与当前实现

当前沟通目录的私聊、群聊、频道，以及收件箱和任务历史打开的工作对话，均由 Communications 接入设计包 Thread。此前各场景共用手动“加载更早消息”按钮。本轮向上接近顶部 160px 时读取下一页，失败暂停并在原位重试，读完隐藏入口；目标是连续阅读，观察信号为无需点击即可读取且原可见消息保持位置。

assistant-ui React 从 0.15.17 更新到 0.15.36，使用 ExternalStoreRuntime 的 hasEarlier / onLoadEarlier、串行 loadEarlier、原生 LoadEarlier 重试和前插滚动保护。设计包只组合可见边界触发器与状态呈现，不持有游标和业务请求；Web 保留原 API、游标与消息合并。删除页面查询 viewport、手算 scrollHeight 和双 requestAnimationFrame 恢复位置的逻辑。生产逻辑集中到已有 Thread，未增加依赖于业务的新通用控件，也未新增永久测试或 fixture。

- hutian-world Web typecheck、官方 build 脚本通过；静态资源已原子更新，本轮没有重启 API 或执行宿主。
- 真实 Chrome 浏览器访问墨菲私聊、Mac 验收助手私聊、聊天工作流群聊、短产品讨论群聊与持仓日报频道。上滚自动请求原历史接口，短会话可自动读取到末尾；抽样可见消息前后偏差 0px，无 pageerror。
- 用户截图对应的沪深收盘报告工作对话：浏览器临时将单次历史请求响应设为 503，确认只请求一次且暂停；原位重试恢复真实接口，成功后提示和历史入口消失。切换至 Windows 验收助手私聊，无旧错误残留。
- 浏览器临时拆分 Mac 私聊的真实已保存消息，验证前插页面：11 个呈现行增加至 78 个，78 个 id 唯一，原可见用户消息位置偏差 0.03125px。此项是浏览器侧受控分页验证，不是声称后端真实历史页本次新增了 67 行；未写入后端数据。
- 原 Communications 文件 ESLint 仍有 10 项未使用变量/空 catch 问题；对比 HEAD 的同文件得到同样 10 项，本轮未新增。

## 其他场景检查边界

Web 当前没有其他手动下一页/加载更多按钮。任务详情的三条运行记录是摘要，完整历史在详情中；执行过程折叠、正文展开和日历翻月不属于数据分页，不改成自动展开。

仍需单独处理的数据访问边界：定时任务/运行列表及任务详情最近 100 条，记忆来源展示 100/50 条；这些接口没有对应下一页游标，本轮未扩写其 API。旧 `?peer=` DirectChat 入口也未暴露分页游标；当前主目录走 `?room=` Communications。不能将本轮结果表述为全站所有历史数据均无限加载。
