# 本周核心链路 MVP

2026-11-13。用户要求本周看到可用 MVP，并明确先打通私聊、群聊、频道、Runtime、记忆和知识库，项目管理后置。优先实现，不新增测试代码、测试框架或回归工程；只做必要编译与最短真实使用检查。

## 用户应当能完成的工作

打开 hutian，继续一段私聊，或建立群聊、主题频道。发送消息时明确选择只发消息或请某位助手处理；成员可在“设置 → 执行配置”保存默认 Runtime，聊天可临时选择本轮使用的其他入口，附带已授权的知识和记忆。回复回到同一对话，资料引用可打开原文，刷新不丢消息与原运行关联。修改成员默认只影响后续新请求，不转移已经开始的运行。

本周不以项目、看板、任务管理或自动编排为入口。原有项目数据和路由保留，不删除已有记录。

## 技术取舍

- 沿用旧 hutian 的 Next.js / React / Tailwind、NestJS + Fastify、TypeORM + PostgreSQL。旧工程按页面或窄机制复用，不搬迁整套数据库和旧世界事件系统。
- Matrix Agents Chat 管身份、房间、消息、引用和历史；其可选宿主负责已明确授权的一次执行。hutian 的页面通过服务端接口接入，浏览器不取得 Matrix、Dock、记忆或知识服务凭据。
- 私聊、群聊和频道共用 Matrix 房间。新房间将用途存入创建信息；当前频道是邀请制的长期主题空间，没有额外实现广播权限或成员发现。
- 相同创造者和助手的私聊使用稳定房间别名，重复打开回到原会话。群聊和频道用独立创建请求标识。
- Dock 负责原生执行。网页与独立宿主分离，网页重开继续观察；宿主或 Dock 故障仍按原回执核对，不承诺任意故障都继续执行。
- 明确选择的 Runtime 必须使用对应的 Dock 应用连接。独立宿主只接受本机运维预先配置的连接别名，不接受网页提供文件路径；每次运行保存原连接私有快照，以免以后更换工作台连接后错误查询另一套服务。
- 首版由宿主读取所选助手在当前房间有权读取的最近 30 条消息，并以有限长度组装上下文。原生 session 迁移或完全连续性不在这一实现中声称已完成。
- 记忆使用已验证的 Scoped Memory Access + Hindsight。为本机工作台建立独立资源与可撤销凭据，保留来源、操作 ID 与处理状态。
- 资料使用已部署的 AnythingLLM 独立知识空间；知识接入保留自己的原文和版本记录，向量索引是派生结果。原文已保存和索引完成分别表达。

## 界面方案

保留旧 hutian 的近黑画布、绿色信号、紧凑导航及既有 shadcn / assistant-ui 组件。当前入口顺序为沟通、组织、知识库、记忆、运行环境。项目管理从主导航后置，原页面仍可访问。

沟通使用固定导航、会话目录和消息工作面。目录按私聊、群聊和频道分组，支持搜索和新建；对象头显示名称、类型与成员。输入区直接表达本次回复对象、Runtime、知识库与记忆使用范围。运行反馈贴近消息和输入区，技术 ID 只在需要核对时展开，不用假在线状态装饰页面。

知识库以资料目录和可读原文为主，添加与检索在同一工作面；记忆以明确保存的内容和来源为主。资料管理不要求用户离开 hutian 到上游运维界面。

外部参考只用于有明确用途的机制：agentes-chat 的群聊协作和来源边界，Multica 的直接开始与运行反馈，Happier 的 Runtime 和 session 状态区分，Cindy 的低门槛开始与设备可用性，Open WebUI 的资料选择与引用核对。研究证据及访问限制见 [界面研究记录](ui-research-2026-11-13.md)。

## 当前边界

当前仍是本机可信单创造者工作台。工作台仍仅供当前拥有者使用，不宣称已完成多人登录或跨创造者授权。第 3 段已补齐业务角色与通信身份的正式关联及人设注入，定义版本与原运行一起保留；真实范围见 [角色聊天交付](stage-3.md)，不把配置目录本身当成全部角色模型。

第 4 段将资源细分为个人工作台、角色私有和会话共享；私聊可用对应角色资源，群聊和频道仅取得本会话共享内容。来源、读取和原操作观察都重新核对范围。当前仍不包含跨创造者授权；详见 [资源范围交付](stage-4.md)。

知识目前支持 Markdown 新增、原文与检索；编辑删除、更多格式和细分资源授权随后按真实资料使用补齐。记忆明确保存后异步整理；没有完成回执不声称已可召回。自动抽取全部聊天、自动调度、跨机器原生 session 迁移、公开部署和发布均不包含在本段。

验收优先看真实消息是否回到原房间、引用是否能打开真实原文、刷新是否保持原记录；不以构建成功代替完整链路和界面验收。
