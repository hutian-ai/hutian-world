# 定时任务失败与原生权限边界

第 7 段增量，保持未提交。以真实股票报告为验收对象，简单消息成功不代表报告成功。

## 现象与证据

11 月 16 日 15:30 沪深、16:30 港股任务均按时进入原生执行，随后因权限请求被拒绝而取消。旧日历将终态 `failed` 显示为“未完成”，未提供独立失败提醒。

原任务专用策略通过异步工具事件匹配审批 ID，再判断富途只读白名单。真实记录中既有审批先到、工具事件后到，也有同一服务并行调用使 ACP 生成独立 elicitation ID；允许范围内的交易日历、自选分组、快照因此被误拒。原生审批元数据带有结构化工具名，但旧 ACP 转换没有保留它。不能将这些记录笼统解释为富途服务不可用。

## 最终边界

- 新定时任务与聊天统一经过 Matrix 标准执行桥，不再走 Hutian 的富途工具白名单或备用命令判断。原 task-client 仅保留转入标准桥的兼容入口，私有旧策略文件不再参与新请求。
- Codex 原生执行负责工具、权限与执行结论。Dock 只透传原生能力和请求；没有明确选择权限时，不再硬编码 `workspace-write` 覆盖适配器默认模式。用户已明确选择的模式仍由原生设置并确认；不修改原生全局配置。
- 原生要求人工决定时，Hutian 可如实显示请求并转交用户决定；不猜测允许，也不把“未匹配应用名单”变成拒绝。无人处理仍可能原生超时或失败，不承诺所有工具无人值守。
- 原生审批的结构化 MCP 标识仅作为协议事实保留，不再用于 Hutian 工具级授权。并行审批在 Dock 有界排队，避免大量长时审批回调耗尽传输处理额度；不扩大传输预算或自动重放决定。

## 用户可见结果

- 终态显示“执行失败”，详情显示原因、原会话与任务入口。独立失败提醒不写入报告的回复引用，避免把系统提醒当作报告交付；原生正常结束并交付回答时，仍忠实记录原回答，不靠关键词重新判定业务结果。
- 新增 `waiting_permission`，日历显示“等待授权”，详情可“去授权”。显式 migration 只扩展状态约束，保留全部旧数据。
- 失败与待授权在原交付会话发送提醒。稳定 Matrix transaction ID 防止反复观察和重启造成重复提醒；失败状态先保存，提醒失败沿同一工作流重试，不重新执行任务。
- 原运行未知时继续核对同一回执，不改成成功或另起重复任务。明确结束后的补跑是新记录，旧失败保留。
- 真实浏览器核对时发现共享设计包与应用各自加载 FullCalendar，导致日历渲染异常；Vite 对 `@fullcalendar/react` 去重后恢复。
