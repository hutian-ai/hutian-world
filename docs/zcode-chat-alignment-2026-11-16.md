## 实现

1. 运行时公开说明与工具按收到顺序直接呈现，取消外层“处理中”标题、分隔线以及等待转输出时头像和布局变化。公开过程复用 Markdown 排版。
2. “工作中”位于最终正文之后；最终正文开始增量输出时仍保留过程。审批的 pending、提交中、结果未知卡片可见时不重复显示通用工作状态。
3. 只有权威状态 completed 且存在答案时默认收起；停止、失败、未知和没有答案的过程保持可读。完成后只收过程，答案和操作栏保留。手动选择持续按原 runId 保存。
4. 连续命令／网页搜索独立分组，公开进展会切断分组。组摘要保留失败或结果待核对状态；用户已展开工具后，新工具加入不会关闭正在阅读的详情。命令和输出优先展示，原始 JSON 放二级详情。
5. 公开文本按 messageId 接收完成事件，跨工具的分段按原位置保留，工具状态更新不重新插入。修正单个 pendingText 误合并或覆盖其他消息的问题。
6. Matrix 的 replyEventId 出现后，只有对应正式消息实际到达才替换临时回复；两者使用同一请求／成员 key。修正历史和运行快照读取时序不同导致整轮短暂消失的问题。

改动位于 `chat-execution.tsx`、`communications.tsx`、`beautiful-ui/tool-chips.tsx`、`assistant-ui/markdown-text.tsx`。设计约束已同步 `DESIGN.md`。本次按核实的交互规则适配既有组件，没有直接搬入 ZCode 整页源码或新增依赖；现有 Beautiful UI 归属说明保留。

首轮没有接入 reasoning 状态。后续已区分“没有摘要正文”和“没有思考生命周期”：Dock 本来提供后者，Matrix 曾与思考正文一起过滤。现已只保留不含正文的开始／完成元信息，详见下方补充。真实文本增量由现有后端事件提供，没有增加前端打字机来模拟流式。

## 运行中状态不占成员副标题

用户澄清转圈保留，问题是“工作中”不应占成员名称下的副标题。重新核对固定 3.17.2 的 `ConversationTurnGroup` / `ChatLoading` 和原始实录 00:52：空等待只显示独立工作状态，有内容后状态跟随本轮末尾，完成后才引入顶部耗时入口。此前虽然把状态放到了正文之后，但它仍处于预先挂载的成员头内部，空等待因此呈现成副标题。

现将运行状态移出成员内容区。没有思考、正文、工具或交互内容时不预挂空头像与姓名；私聊只显示工作状态，群聊／频道在同一行标明成员。请求尚未取得活动记录时使用同样的独立等待行，不在生命周期切换中重新出现副标题。有内容后恢复成员身份和原过程；等待审批继续由请求卡接管。Spinner 保留，完成与异常的原折叠规则不变。

真实 Mac 私聊从空等待、公开说明、只读 `sleep 8` 工具运行到最终完成连续通过：空等待无成员头、转圈存在，内容出现后状态位于成员区外末尾，结束后工作状态消失且顶部耗时与答案可见。浏览器无页面错误或横向溢出；Web 类型检查与生产构建通过。群聊身份分支本次仅做源码核对，没有额外发起群聊。证据为 `.local/chat-summary-20261116/loading-*`。没有更改后端、Runtime 或模型，改动仍保留未提交。
