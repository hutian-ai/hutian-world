# 定时任务与日历交付 · 2026-11-16

本轮按用户要求先交付可验收的定时任务与日历，仍属第 7 段；Matrix 配套仍属第 20 段。源码保持未提交，没有切换 Hatchet、拆仓、推送或发布。

## 实现范围

- 使用已安装的 DBOS 5.5.0 官方 `applySchedules` 与单并发队列驱动后台时钟，替代 API 自写 `setInterval`。每 15 秒协调到期安排。RRULE + Temporal 继续统一计算一次性、周/月、每隔 N 天、多时段及日历预览；没有把这些业务规则强行转换成 Cron。参考：[DBOS Scheduling Workflows](https://docs.dbos.dev/typescript/tutorials/scheduled-workflows)。
- DBOS 步骤只持久化本期记录与待协调 ID；子工作流从工作流层启动，沿用原 `schedule:workspace:id`。重启立即核对原安排与活动记录，按同一 ID 继续。没有重建历史、修改原生权限或重派发结果未知的任务。
- 新增 Matrix 宿主的轻量房间读取：只读取房间种类和当前成员，不读取历史消息及其他执行文件。安排保存、发送任务消息、定时派发和资源范围校验使用这个入口；进度只读取当前原消息对应的 `/api/agent/status`。
- 完成、无需报告和失败来自原回执。查询不可确认时显示“结果待核对”，不继续保留误导的“执行中”。已保存的执行结果继续沿原事务 ID 交付；交付暂未确认时保留原运行，独立于新任务派发。
- 停机后按原计划时间逐项记录错过的时段，每个安排每轮最多处理 32 个时段。超过启动窗口不补跑，上一期尚未结束不重叠；未展开完的历史留待下一轮处理。
- 日历保留已到点、尚未生成执行记录的预计项，避免扫描间隙短暂消失。通信目录暂不可读时仍可进入日历与运行历史。
- 修复 React Router 迁移后仍直接调用 `history.pushState/replaceState` 的问题。点击日历事件、列表详情、筛选、周/月/日程与日期切换现在通过路由导航同步页面和 URL。
