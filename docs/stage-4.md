# 第 4 段：角色私有资源与会话共享范围

2026-11-14。用户明确先完成角色资料与记忆范围，模型连接延迟排查暂缓。上一段已单独本地提交为 `10bb600`；对应 Matrix 第 18 段已单独本地提交为 `45321ac`。本段保持未提交，不推送或发布，不新增测试、fixture 或 CI。

## 现在能用什么

- 成员详情增加“资料与记忆”，打开该角色的私有知识库和记忆。
- 知识库、记忆页面按个人工作台、角色私有、当前会话共享分别管理。新增、原文、检索和记忆操作状态均沿同一个范围；来源链接携带范围，刷新可再次核对。
- 新保存内容先明确归属。原工作台资料和记忆保留原位置，不自动搬迁、复制或共享。
- 与同一角色的两人私聊可使用角色私有资源和当前会话资源。群聊、频道只使用当前会话明确共享的资源，不回退检索整个个人工作台或角色私库。未关联正式角色的旧助手也只取得本会话资源。
- 输入区显示本次可用范围，并提供会话资料、会话记忆和适用时的角色资源入口；知识、记忆开关仍决定本轮是否检索。
- hutian 不允许向私聊增加成员；多人讨论需另建群聊。已有私聊实际不再是两人时，服务端不提供角色私库。
- 重复观察已有执行沿用原上下文和回执，不按新的资源配置再次准备输入。

## 实现与边界

范围标识由当前创造者 ID、正式角色 ID 或 Matrix 房间 ID 稳定派生。每次入口先核对角色拥有者或当前 Matrix 参与关系，浏览器不能提交 bank、知识空间、文件路径或凭据。私聊类型取自不可变的 Matrix 建房信息，另核对实际两人参与关系；不以客户端标签或角色名字作为授权。

每个角色或会话范围对应独立 AnythingLLM 工作空间、原文目录和独立 Hindsight bank。记忆继续通过 Scoped Memory Access 的受限凭据访问，不将管理员密钥交给浏览器或 Runtime。首次显式保存记忆时，可信本机宿主调用接入层已有的管理 CLI 准备单范围资源和凭据；它仍逐次校验当前凭据，已撤销凭据不会自动重签。只读空范围不会自动签发凭据。

本机管理命令由操作员用 `pnpm resources:setup` 写入 `.local/memory-provisioner.json`，动态 client 文件在 `.local/resource-clients/`，新知识原文在 `.local/resource-libraries/`，均保持私有权限。没有新增业务数据库表，没有复制记忆、消息、运行或索引账本；模块仍负责原有事实。

群聊共享表示内容可以用于本会话成员，之后邀请的新成员也属于该共享范围。当前仍为可信本机单创造者版本，不承诺跨创造者身份认证、历史内容撤回、成员变更时回收已读副本、或隔离可读取宿主私有文件的本机进程。没有自动从私聊提炼并共享记忆，没有把角色和岗位合并，也没有盘点 Runtime 自有资源。

原始请求的 material 中保存本次范围说明、检索开关状态和实际取得的片段及来源。已发送内容不会因后来变更而回收；后续新请求重新检查当前范围。模型记住或复述过的内容不等于其获得了新的资源访问权。

## 使用与验证

入口：http://127.0.0.1:3340/members 。进入墨菲的“资料与记忆”管理私有资料；在群聊输入区打开“会话资料 / 会话记忆”明确共享内容。

已在真实浏览器保存“墨菲研究资料使用约定”“墨菲报告阅读偏好”及“技术分析讨论共享约定”，原文与知识索引保存成功，角色记忆整理完成；私有与会话目录互不包含对方资料，私聊与群聊范围提示正确，1440px 桌面无横向溢出或页面脚本错误。TypeScript 与正式构建通过。

两次真实调用均通过家里电脑 Codex 完成，耗时约 140 秒与 136 秒。私聊回复列出角色私有知识和记忆并附范围来源链接；群聊仅引用会话共享资料，明确本轮未取得角色私有内容。核对宿主保存的原请求 material 与最终 prompt，私聊包含私有知识、记忆，群聊不包含它们，仅有本会话共享资料；不是只采信模型自述。

角色与会话记忆分别保存后，两份范围凭据读取自身返回 200、互读返回 403。私聊回复中的知识与记忆链接打开了实际原文；将私有文档编号放进群聊范围链接，页面明确拒绝显示该原文。共享记忆是在群聊调用准备参考材料之后完成整理，因此不将该次群聊回复声称为已经召回新共享记忆。未重复派发同一运行。

本段没有定位或修改原生网络回退，延迟仍按用户要求暂缓。私有原始证据保存于根工作区 ignored `.local/stage-4-resource-scopes/`。
