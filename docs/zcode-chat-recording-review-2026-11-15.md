# ZCode 聊天文本流：实录与源码对照

本轮完成参考产品实录与定向源码核对，尚未把对应改动实现到 Hutian，不能称为 Hutian 已对齐，也不能将 ZCode 实测称为 Codex 实测。用户当前要求是按真实聊天文本流学习，不是继续拼接竞品控件。

## 录制范围与证据

- 本机 ZCode **3.17.2**，界面显示 GLM-5.3 / 最高、变更前确认；未升级客户端或调整模型、权限。
- 2026-11-15 北京时间约 19:26–19:29，以 ScreenCaptureKit 仅捕获 ZCode 窗口；2048 × 1152，原始连续视频 **202.37 秒**，约 6.6 MiB。
- 原始视频（不提交）：`../../.local/zcode-chat-recording-20261115/zcode-full-flow.mp4`。
- 辅助核对：同目录 `frame-*.png` 为每两秒抽取帧，`timeline-ocr.json` 是 OCR 定位辅助而非事件权威，`source-review.md` 为详细源码路径与许可记录。
- 开始前的普通系统录屏黑屏，替代窗口捕获最初停在后台旧画面；用户将 ZCode 置于前台后，确认画面已刷新才开始正式视频。失败的 capture-check / window-check 文件不属于验收证据。
- 请求分别检查 macOS、Node.js 与磁盘空间，用真实只读命令触发过程文字和工具。一次 `sw_vers` 权限确认仅选择“允许这一次”；没有选择始终允许或完全访问。
- 视频保留了输入纠正、权限卡停留和结束后的人工展开。因此 UI 的“已工作 55 秒”包含等待操作，不作为模型或工具速度结论。

## 实录时间轴

下列时刻取自视频帧，约有两秒定位误差。

| 原视频时刻 | 真实画面 | 交互含义 |
| --- | --- | --- |
| 00:00–00:50 | 空白新会话；输入、修正为完整请求；命令文本中的斜线触发候选列表，退出后发送 | 原始视频包含输入过程，不是从结果页开始 |
| 00:50–00:52 | 用户消息进入右侧；其下出现轻量“工作中”；输入框转为后续排队提示，按钮变停止 | 正常等待没有连接 Runtime 的说明，也没有预先展开的执行面板 |
| 00:54 | 思考摘要行保持折叠；公开过程正文只出现“我准备依次”，其下仍有工作中 | 公开过程文字真实增量出现，思考摘要与正文是不同层 |
| 00:56–01:24 | 首段文字完整、工具摘要出现；底部出现 sw_vers 权限卡，普通工作中让位 | 工具与文字同序进入这一轮；等待用户决定不伪装成仍在生成 |
| 01:26–01:28 | 单次允许后恢复工作中；相邻工具变为“终端 · 2 个命令” | 工具结果默认以摘要呈现，不铺开原始输出 |
| 01:30–01:40 | “前两项已拿到结果…”进展出现在工具之后；随后追加 df 工具和下一段思考摘要 | 是文字—工具—文字—工具的连续内容流，而非几个独立状态页面 |
| 01:42–01:44 | 最终表格已经出现，解释文字继续增长；先前过程仍在，工作中仍在最末尾 | 最终答案开始输出不等于整轮结束，不应提前收起过程 |
| 01:46 | 工作中消失；前面的思考、公开过程与工具收进“已工作 55 秒”；最终答案与操作区留在外面 | 真正终态才发生整体收纳 |
| 约 02:16–02:58 | 手动展开已工作入口，再展开工具组、单条命令的实际输出 | 整轮过程、工具组、单工具是不同折叠层级；最终答案仍独立存在 |
| 约 03:00–03:22 | 手动重新收起，最终答案保留，输入框恢复后续提问 | 收起过程没有删除答案，也没有新增一条重复最终回复 |

## 从实际路径得出的采用方向

本次正常主流程采用“本轮内容末尾轻量等待 → 按事件顺序追加文本/工具 → 最终答案继续流式输出 → 真正结束后收纳过程”。此前把普通等待一律迁到 agentes.chat 输入框活动条的建议，不再作为本轮文本流方案。agentes.chat 已确认的成员配置归属不受此修正影响。

| Hutian 当前源码 | 与本次实录的差异 | 后续适配要求 |
| --- | --- | --- |
| `chat-execution.tsx` 有过程块时即显示外层“处理中”折叠触发器与分隔线 | ZCode 运行中没有这个外层标题，文字和工具直接连续出现 | 运行中直接显示过程内容；完成后才引入本轮耗时折叠入口 |
| `ChatExecution` 位于正文前，等待状态属于其顶部 | ZCode 工作中始终在当前内容末尾，连最终正文流式增长时也一样 | 状态行放到该成员本轮输出末尾，单一实例；审批时让位 |
| `compactWaiting` 切换头像大小和整行布局 | 实录主要是同一阅读列中内容自然增长 | 保持成员标识和阅读列稳定；群聊所需身份保留，避免等待转输出重新排版 |
| 过程和最终正文已分区、终态默认折叠 | 方向已有部分一致，但标题出现时机和输出流仍需修正 | 复用现有 Dock 真事件与稳定消息关联，不将文本动画当流式传输 |

这张表记录 11 月 15 日源码差异与实施依据，当时未修改 Hutian 产品实现。11 月 16 日按用户继续授权完成的实现和实际验收见 [对齐交付](zcode-chat-alignment-2026-11-16.md)，不要将两个日期的证据混为一次验收。
